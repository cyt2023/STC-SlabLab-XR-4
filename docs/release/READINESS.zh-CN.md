# 桌面版上线评审与鲁棒性预案

日期：2026-09-16。对象：STC-SlabLab-XR-4 源码及现有 macOS 安装包。
结论：暂不满足公开上线标准。下列修改是源码修复，尚未重新构建并替换现有安装包。

## 本轮证据和修复

- 实际打开打包 App，首屏变量卡片遮挡选择目录按钮。代码中按钮下沿为 63、卡片上沿为 75，区域相交。已将按钮移至 y=116，下沿 87，与卡片留出 12 单位间距；简化按钮为 CHOOSE FOLDER，保留变量名大小写。需要重新构建后验证视觉效果。
- 自动点击 Continue 与 Next 后未观察到页面推进；尚未确定是自动化输入还是应用流程原因，不计作通过。
- 原 MatPlot 只有执行并发信号量，每次请求仍创建排队线程。已增加总接纳容量（默认 81，包含正在接收、排队、执行的任务），满载返回 429 和 Retry-After。上传分块读取，数据限制 64 MiB、契约 2 MiB；拒绝、取消或线程创建失败时释放容量并清理临时文件。
- 加强数据模型校验：空变量、空时间帧、非有限数值映射、重复轴桶编号、歧义单元格编号、非有限共享色阶均提前拒绝。
- 网格范围计算改为逐单元汇总极值，避免将整张网格的有效值再拼接一份。
- 自动化离线回归 26 项通过（既有 20 项、新增 6 项）。覆盖数值、缺失值、契约、摘要及上述异常。未调用收费模型。
- 保留仓库原有未提交的启动脚本、后端自动启动器和客户端改动；未覆盖旧安装包。MatPlot 位于 Git 子模块，发布时必须同时包含子模块修改。

## 目标交互

打开应用 → 导入数据 → 确认坐标和变量 → 选择范围 → 配置分析 → 查看结果。

每步只提供一个主操作；前置条件未满足时禁用下一步并给出可执行提示。返回保留已确认配置，改变数据或范围后将后续结果标记为旧结果。每个耗时操作有进度、取消、失败后重试，不依靠日志传达错误。

桌面使用固定页面布局，避免继续把 VR 空间面板缩放充当桌面表单。头部显示步骤，中央显示当前任务，底部显示主要操作。窄窗口改为换行/滚动，不无限缩小文字。列表、错误提示和长变量名必须有独立空间；不强制变量名大写。

## 多图与多变量

当前已有最多两个历史并排视图，但 analysisNodes 历史对象仍累积。建议结果库保存完整记录和缩略图；主区显示一张，可固定两张对照，其余按需载入。关闭视图只释放显示资源，删除结果要与关闭区分。纹理采用内存预算和最近使用淘汰，原图保存在磁盘，避免悄悄丢失分析历史。

图表记录必须绑定 datasetId/version、变量、单位、时间、深度、缺失值策略、色阶和生成状态。切换数据集后迟到的异步结果不得覆盖新工作区。

变量采用可搜索多选。相同单位可共用色阶；不同单位默认拆开显示，只有显式选择归一化才允许无量纲比较。当前后端会将不同单位标为 mixed units 却仍共用数值范围，需要上线前修正。

队列满载应在前端明确提示稍后重试，不能无限重试。多个网格并发提交可能出现部分单元成功：必须保留成功项并允许只重试失败单元；当前 S4D 提交需要补这一层恢复能力。服务重启后的任务恢复、取消、历史状态和磁盘保留策略仍待实现。

## 数据集适应性

现有分析模型仅声明 uint8、ZYX 存储，不能承诺任意数据直接导入。现有导入和分析注册机制也不是同一条路径：S4D 从 datasets/*/manifest.json 注册数据，UI 能发现 RAW 不等于后端能分析它。

应建立统一导入管线：格式识别 → 元数据映射 → 文件与数值验证 → 预览 → 原子注册 → 分析。格式适配器输出同一内部数据模型；按用户实际格式确定 CSV、NetCDF/HDF5 的实现顺序。

校验内容：形状/存储顺序/字节序/类型、时间排序与重复、经纬度/投影/空间范围、真实单位和缩放、缺失值、变量间坐标对齐、文件大小与权限。失败要指出文件和字段，并保留原数据。禁止未知单位自动推断成物理量，禁止对不同地区套用香港地图。

大数据导入需要后台任务、进度和取消；读取采用切片/分块并设置可配置内存预算。测试必须包含非演示数据和未参与开发的真实数据。

## 一键启动及故障预案

当前 package-macos.sh 只复制 App、后端源代码和脚本；Setup Backend.command 仍调用系统 Python 和在线 pip。已存在的自动启动器检查 .venv 标记，不会替用户安装环境。开发机能运行不代表干净电脑可运行。

上线方案：随 App 提供匹配芯片架构的独立 Python 运行时或打包后的后端；固定依赖版本；不复制开发机虚拟环境。服务与数据资源在 App 内，缓存/日志/用户数据在 Application Support，支持移动 App 和只读安装目录。

启动状态：准备环境 → 启动服务 → 校验服务身份及能力 → 就绪。服务启动失败时提供重试、查看诊断、继续浏览数据。端口冲突自动选择空闲端口并将地址传给前端；不要结束不属于本应用的进程。退出仅清理本实例拥有的子进程，崩溃后有有限次数退避重启。

模型密钥不能打包给所有用户。基础数值分析和确定性图表应能离线完成；AI 功能首次使用时配置提供方，或使用产品服务端代理。缺少密钥/断网时明确区分不可用的 AI 能力，不能把整个工作区阻断。

更新保留上一安装包与用户数据；生成版本化诊断包，日志脱敏。数据格式迁移先备份，失败回滚。

## 上线验收门槛（尚未完成项均不可标为通过）

| 范围 | 场景 | 通过标准 |
| --- | --- | --- |
| 干净安装 | 无 Python、无开发工具、断网、首次启动、移动 App | 基础导入/分析可用，不要求终端配置 |
| 服务 | 端口占用、重复启动、进程退出、超时 | 界面可恢复，无静默失败、无误杀 |
| 导入 | 空目录、缺文件、损坏文件、中文路径、权限不足 | 指出原因；不产生半注册数据 |
| 数据 | 多变量、不同单位、不同坐标、全缺失、常数、乱序时间 | 结果正确或明确拒绝 |
| 容量 | 1/9/81 图；重复提交；达到容量上限 | 有界排队；拒绝可理解；失败不泄漏资源 |
| 会话 | 连续切换变量/数据 100 次、分析 2 小时 | 内存不持续无界增长，旧任务不污染新结果 |
| UI | 1024×768、1280×800、1920×1080、Retina、长文字 | 控件可达，文字不重叠、不裁掉关键内容 |
| 流程 | 前进/后退、取消/重试、关闭图、恢复历史 | 状态一致，用户配置不意外丢失 |
| 性能 | 常用交互和大文件导入 | 目标交互反馈 ≤100ms；耗时工作不阻塞主线程，需实测 |
| 发布 | 干净机器端到端测试、签名与系统检查、版本回退 | 从安装到导出完成，失败能恢复 |

实施顺序：先解决独立运行与统一数据注册，再完成桌面线性流程和多图资源管理，最后跑上述矩阵并重新打包。26 项离线测试不能代替安装包验收和真实机器性能测试。
